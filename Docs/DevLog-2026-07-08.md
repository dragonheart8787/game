## Patch 6:Constraint 節點 + Bind 能力

### Constraint 節點(新實作)

- `ENovaAbilityConstraintType { None, TetherToActor }` + `FNovaAbilityConstraintNode`
  (`ConstraintType` + `TetherDurationSeconds`),純資料、可序列化,比照
  Shape/Path/Spawn/Affect 的 pattern;`FNovaAbilityGraphDef` 新增 `Constraint` 欄位。
- Pipeline 擴為 Shape → Path → Spawn → **Affect(收集命中目標)** → **Constraint**。
  `ExecuteAffect` 改為回填 `OutAffected`;`ExecuteConstraint` 對「最近的被影響
  目標」生成 tether。
- `ANovaTetherLink`(新 actor,比照 `ANovaBlockingWall` 的持久 actor pattern,
  但**開 tick**):每幀用 `DrawDebugLine` 從玩家畫到被錨定目標(紫色 = Bind
  家族的量子鎖鏈視覺),持續跟隨移動中的目標,`TetherDurationSeconds` 後
  `SetLifeSpan` 自毀。

### Bind 能力

- `ENovaAbilityAffectType` 追加 `Slow`(**append 在最後**,保持 Damage=1/Block=2
  對既有 DataAsset 的序列化穩定);`FNovaAbilityAffectNode` 加
  `SlowSpeedMultiplier` / `SlowDurationSeconds`。
- Bind = Sphere(判定半徑 400)+ Instant + **Slow(50%/3s)** + **TetherToActor(3s)**,
  cd 2.0s、energy 15。定義在 C++ 建構(`MakeBindDefaultDef`),`BeginPlay` 註冊,
  **不佔用 CastAbility1/2**;比照 Edgewall 在 Patch 3 先進 C++、Patch 4 才
  DataAsset 化的路徑 —— 若日後放 `/Game/Data/Abilities/DA_Ability_Bind`,會自動
  蓋過 C++ 預設。
- `ANovaDummyTarget` 是純 `AActor`(無 CharacterMovement),因此加一個可查詢的
  名目 `BaseMoveSpeed` + 自復原 slow 狀態(`ApplySlow`/`GetCurrentMoveSpeed`/
  `IsSlowed`,用 timer 復原,不需 tick),讓「降速→復原」可驗證。
- Slow 只作用於「真的可被降速」的目標(`ANovaDummyTarget`),因此 Sphere 無弧度
  過濾時,tether 不會誤錨定到範圍內的觸發區。

## PIE 迴歸:NovaBindTestDriver(8/8 全綠)

方法沿用既有 pattern:MCP `add_to_scene_from_class` 生成 driver(記憶體內、
不存關卡)→ `StartPIE(warmupSeconds:0)` → 固定 sleep → `StopPIE` → 讀
`Saved/Logs`。序列(game-time)與結果:

- cast@1.0:首次 Bind 成功、同幀重施放被 `CastBlocked_Cooldown (2.0s)`、
  energy 100→85(−15) ✅✅✅
- verify-slow@1.5:dummy 速度 300→150(50%)、tether 已生成 ✅✅
- move@2.0 → verify-follow@3.5:tether 端點跟到移動後的 dummy,
  **drift 0.00cm** ✅
- verify-restore@5.0:slow 到期速度復原 300、tether 依 duration 釋放 ✅✅
- 決定性判別:tether `EndPlay` 記錄 final endpoint `V(250,300,302)` == 移動後
  dummy 位置 → 證明是**逐幀跟隨**而非固定一條線。

### 除錯筆記(值得記住)

- 首跑 verify-follow **FAIL,drift 恰好 300cm**(== 我把 dummy 右移的量)。
  看 log 幀號:`move` 與 `verify-follow` 落在**同一幀**(frame 77)。原因:
  **編輯器非前景時 PIE 會被節流到 ~3 FPS**(每幀 ~333ms),原本 move@1.6 /
  check@1.8 的 0.2s 間隔擠進同一慢幀,tether 該幀的 Tick 已在 move timer
  之前跑完 → check 讀到搬移前的端點。這是**測試時序**問題,不是功能 bug。
- 修法:把 move→check 間隔拉大到 1.5s(跨多幀,即使 3 FPS 也穩),並加
  `EndPlay` final-endpoint log 當決定性判別。重編、重跑 → 8/8 全綠。
- 教訓:PIE 迴歸中「改狀態→立刻驗證」的兩步之間必須留 ≥~0.5s(數幀),
  因為背景編輯器 PIE 幀率極低。已更新對應記憶。
